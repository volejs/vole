# Runtime VM

`vole-runtime` 的核心执行单元是 `Vm`。它封装 QuickJS 的异步运行时，并在启动时完成模块加载器、全局 Web API、`vole:*` 原生模块和 runtime 生命周期能力的初始化。

## 组成

| 字段 | 说明 |
| --- | --- |
| `runtime` | `rquickjs::AsyncRuntime`，负责 QuickJS 异步 runtime。 |
| `ctx` | `rquickjs::AsyncContext`，当前 VM 的 JS context。 |
| `until_registry` | runtime 级 `UntilRegistry`，用于托管 `vole:until` managed scope。 |

## 初始化流程

`Vm::new()` 会按顺序完成：

1. 加载当前工作目录下的 `.env`。
2. 创建 `AsyncRuntime`。
3. 使用当前工作目录创建 `ModuleResolver`。
4. 创建 `ModuleLoader` 并注册 runtime native module provider。
5. 创建 `AsyncContext::full`。
6. 将 `UntilRegistry` 存入 JS context userdata。
7. 调用 `bindings::init()` 初始化全局 API、raw backends 和 JS shims。
8. 注册 unhandled promise rejection tracker，将未处理 rejection 转发为全局事件。

## 执行入口

| 方法 | 说明 |
| --- | --- |
| `eval(code)` | 执行一段 JS 代码，返回格式化后的 JS value 字符串。 |
| `eval_file(path)` | 执行 JS / TS 文件；`.ts`、`.mts`、`.tsx` 会先转译。 |
| `with_context(fn)` | 暴露 `Ctx` 给 Rust 调用方执行自定义操作。 |
| `run_tests(files)` | 先执行测试文件，再导入 `vole:test` 调用 `run()`。 |

## TypeScript

文件执行时，`eval_file()` 会根据扩展名判断是否需要转译：

- `.ts`
- `.mts`
- `.tsx`

转译由 `vole_module::transpile_typescript()` 完成，然后作为 ES module 交给 QuickJS 执行。

## 异步收尾

`eval()` 和 `eval_file()` 完成后都会 drain runtime 级 managed `WaitUntil`：

```ts
import { WaitUntil } from "vole:until";

const until = new WaitUntil();
until.waitUntil(Promise.resolve().then(() => console.log("background")));
```

默认 drain timeout：

| 场景 | 超时 |
| --- | --- |
| 普通执行 | `30_000ms` |
| 测试执行 | `60_000ms` |

## 注意事项

- `Vm` 是 async-first，调用方需要在 Tokio runtime 中使用。
- `eval()` 适合短代码；模块执行应优先使用 `eval_file()`。
- `eval_file()` 会运行少量 pending jobs，并等待 timer idle，但不是完整浏览器事件循环。
- 未处理错误会尝试 dispatch 到全局 error / rejection 事件系统。
