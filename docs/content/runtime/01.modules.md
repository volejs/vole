# Runtime Modules

vole 的模块系统分为两层：

- 对用户公开的 `vole:*` 模块。
- 仅供 JS shim 使用的 `vole:raw:*` 原生模块。

runtime 在创建 VM 时将 native module provider 注册到 `ModuleLoader`，由 provider 按 specifier 返回对应的 Rust `ModuleDef`。

## Native module provider

`RuntimeNativeModuleProvider` 负责加载 `vole:raw:*` 模块。

当前注册的 raw 后端包括：

| raw module | 对外模块 |
| --- | --- |
| `vole:raw:dns` | `vole:dns` |
| `vole:raw:env` | `vole:env` |
| `vole:raw:exec` | `vole:exec` |
| `vole:raw:ffi` | `vole:ffi` |
| `vole:raw:fs` | `vole:fs` |
| `vole:raw:http` | `vole:http` |
| `vole:raw:os` | `vole:os` |
| `vole:raw:path` | `vole:path` |
| `vole:raw:signal` | `vole:signal` |
| `vole:raw:socket` | `vole:socket` |
| `vole:raw:tcp` | `vole:tcp` |
| `vole:raw:udp` | `vole:udp` |
| `vole:raw:until` | `vole:until` |
| `vole:raw:wasm` | `vole:wasm` |

## Public modules

公开模块由 `crates/modules/src/js_shims/*.js` 组合 raw 后端，形成稳定 API。

例如 `vole:env`：

```ts
import { get, set, load } from "vole:env";
```

JS shim 内部才会访问：

```ts
import { __std_env_get } from "vole:raw:env";
```

## 访问控制

`PUBLIC_VOLE_MODULES` 是允许用户导入的 `vole:*` 模块列表。raw 模块不是公共 API，普通用户代码不应该依赖 `vole:raw:*`。

## 设计边界

- `vole:*` 是 vole 自己的标准模块命名空间，不是 Node.js 兼容层。
- raw module 是实现细节，可能随 runtime 内部重构变化。
- 新系统能力应该先落到 raw binding，再由 JS shim 暴露更稳定的 API。

## 实现位置

- `crates/runtime/src/native_modules.rs`
- `crates/modules/src/module_names.rs`
- `crates/modules/src/js_shims/`
