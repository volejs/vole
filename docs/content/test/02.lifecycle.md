# Test Lifecycle

`vole:test` 的生命周期很简单：测试文件只负责注册测试，真正运行由 CLI 最后统一调用 `run()`。

## 全局测试

不在 `describe()` 中注册的测试会先运行：

```ts
import { test } from "vole:test";

test("top-level", () => {
  // ...
});
```

## Suite 测试

`describe()` 会创建当前 suite，并把内部 `test()` 归入该 suite：

```ts
describe("suite", () => {
  test("case", () => {});
});
```

执行顺序：

1. top-level tests
2. suite by suite
3. suite `beforeAll`
4. 每个测试的 `beforeEach`
5. 测试函数
6. 每个测试的 `afterEach`
7. suite `afterAll`

## Hook 边界

当前 hook 只在 `currentSuite` 存在时生效：

```ts
beforeEach(() => {
  // 只有写在 describe() 内才会注册到 suite
});
```

也就是说，top-level `beforeEach()` 不会影响 top-level tests。

## 注意事项

- suite 目前不支持嵌套 suite 语义。
- 没有 `test.skip` / `test.only`。
- 没有 snapshot。
- 没有 mock API。
- 同一个 VM 内注册的测试会保留到 `run()`。

## 建议

- 简单 runtime 测试直接使用 `test()`。
- 有共享状态时使用 `describe()` 和 hook。
- 异步测试直接返回 Promise 或使用 `async` function。
